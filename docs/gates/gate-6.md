# Gate 6: the first-afternoon rehearsal

Run on 2026-11-08 (early morning) on the reference Mac (Apple M1 Max, 32 GB, macOS 27, Electron 45.2.1, iii 0.25.0, Ollama via Homebrew), twice: against the packaged `PIM.app` built by `npm run package` (unsigned, arm64, 416 MB on disk, 160 MB DMG), which started its own bundled engine, and against the development build joined to the repository engine. Both runs are the Playwright script `tests/e2e/rehearsal.mjs` (`npm run rehearsal [--packaged]`) over the corpus in `tests/corpus/README.md`, from a fresh profile each time. Nothing waited on a model: Ollama was running and enriching in the background, and every step was satisfied by deterministic stages.

## What was run

1. A fresh install: the first-run screen, the sample note captured and found by a remembered word, "Done".
2. Five pieces: a web page clipped through the capture panel (paste, Return, receipt), then a PDF, a whiteboard photo, a voice memo and a video dropped (the drop handler's call with each file's path, since the operating system's drag cannot be scripted).
3. Each piece found in the Library by a remembered phrase as typed, opened from the hit, and checked at the passage: the passage row marked, plus the readable frame, the rendered PDF page, the highlighted OCR box, or the player positioned at the line.
4. Two suggested links accepted in the Inbox by a click each; the graph opened from the web page.
5. The five exported, every link in the package checked, the package imported into a fresh vault and compared row by row; a backup taken while the app ran and a restore test into a temporary folder.
6. By hand through the IPC on a third instance: restore into a new folder with the app switching to it, a capture after the switch, and the vault folder changed back and to an empty folder.
7. Unit tests: 29 across vault, contracts and the model worker, including 7 new ones for export, import, backup and restore.

## Found and fixed during the gate

- The packaged app passed `III_URL` through to `iii compose`, which reads that variable as "an engine already exists" and started nothing; the app now strips it (and `ELECTRON_RUN_AS_NODE`) from the daemon's environment. `III_URL` is also reserved inside the compose file's `environment`.
- A quoted command in a compose `run:` line is a YAML scalar followed by junk; run lines are written as one JSON string.
- The bundled web-preserve worker declared `require` twice once rolldown added its own shim; the worker's module resolver was renamed. As a second instance of the app binary it also had to be given its own profile directory.
- Importing `@pim/vault` from plain Node failed on a TypeScript parameter property in the graph class; it is an explicit field now, in line with the rule recorded in M1.
- The stage order: `link` now runs right after `extract` and again after `enrich`, and only one model stage runs at a time, so a deterministic suggestion never waits behind a model (the rehearsal's "no step waits on a model").
- Text captures from the first-run screen flowed through the same path as the panel; the PDF in the corpus had text running past its page (an artefact of the Gate 2 corpus), so the corpus got a proper one.

## Not verified by automation

The native folder pickers behind the Settings buttons (the IPC takes a path for scripts and shows the dialog otherwise); the inbox's keyboard review (`j`, `k`, `a`, `r`, covered in Gate 4); an edge click on the graph canvas (Gate 4); the DMG on another Mac, where Gatekeeper will warn because the app is unsigned; and the media worker from a Python runtime other than the repository's `.tooling/py`.

## Deviations

The Python runtime is not packaged (spec 5): Settings names the environment that `infra/setup.sh` builds, and the first-run screen says audio and OCR are unavailable without it. The app is unsigned and not notarised. Backups are taken by hand; the daily encrypted snapshot waits for encryption in v0.2. Embeddings are not exported; an import reopens enrichment, which rebuilds them under the current model and skips extraction already done with the same model digest.
